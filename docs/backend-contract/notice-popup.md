# 로그인 후 공지 팝업 계약 (제안, 서버 미구현)

앱이 기대하는 형태다. 서버 세션과 합의 전이므로 구현 전에 확인한다 (`features/notices/api/notice-api.ts`가 이 형태를 zod로 검증한다).

`GET /api/notices/popup` (Bearer)

```json
{
  "code": "SUCCESS",
  "data": {
    "notices": [
      {
        "id": "100",
        "title": "서비스 점검 안내",
        "body": "본문 (일반 텍스트, 줄바꿈 \\n)",
        "image": { "url": "https://cdn.example.invalid/n/100.jpg", "width": 800, "height": 500, "alt": "대체 텍스트" }
      }
    ]
  }
}
```

- 서버가 대상 계정, 노출 기간, 우선순위(앞에 올수록 먼저)를 정해 걸러 내려준다. 앱은 거르지 않는다.
- `id`는 문자열/숫자 모두 허용(앱이 문자열로 바꿈). 공지가 바뀌면 id도 바뀌어야 "오늘 하루 보지 않기"가 새 공지에는 적용되지 않는다.
- `body`는 **일반 텍스트**다. HTML/마크다운은 렌더하지 않는다(주입 방지). 서식이 필요한 긴 공지는 이미지로 만들거나 상세 화면(WebView)로 연다.
- `image`는 선택. `url`은 **https만** 허용하며, `width`/`height`(원본 픽셀)는 필수다: 앱이 이미지가 로드되기 전에 높이를 잡는다. CDN 캐시 가능한 URL이어야 한다(앱은 디스크 캐시함). 가로 800~1200px 정도로 올린다.
- 공지가 없으면 `notices: []`. 실패해도 앱은 팝업만 건너뛴다.
