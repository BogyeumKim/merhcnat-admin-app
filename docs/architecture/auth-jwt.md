# 인증(JWT) 설계

백엔드 JWT는 아직 없다. 이 문서는 확정된 정책과 그에 맞는 클라이언트 설계다. API 클라이언트 코드는 계약이 정해진 뒤에 만든다.

## 확정된 정책 (사용자 결정)

- **refresh token 없음.** 서버도 만들지 않는다.
- **앱을 실행하면 항상 로그인이 필요하다.** 토큰은 어디에도 저장하지 않는다 (메모리에만). 앱 종료/강제 종료 = 로그아웃.
- 서버가 API 요청을 받을 때 토큰 만료까지 남은 시간이 약 10분 이내이면 **서버가 토큰 수명을 늘려준다** (슬라이딩 만료).

현재 코드: `features/auth`의 `SessionProvider`는 토큰을 메모리에만 두고 영속 저장소를 쓰지 않는다 (이 정책에 맞게 수정함).

## 슬라이딩 만료 설계

조사 요약 (출처 대부분 문서/블로그. 같은 개념이 여러 곳에서 반복):

- **슬라이딩 + 절대 상한**이 표준 조합이다. 활동할 때마다 수명을 늘리되, 총 수명에 상한을 둬서 계속 쓰면 영원히 안 끊기는 일을 막는다 (IdentityServer 문서: 슬라이딩 + 절대 만료 둘 다 둔다). **서버에 절대 상한을 두도록 요청한다** (예: 근무시간 기준 상한).
- "남은 시간이 임계값 이하면 응답 헤더로 새 토큰을 내려준다"는 방식은 약한 출처 하나만 있었고 실제 제품으로 검증하지 못했다. 다만 레거시 앱이 이미 응답 `Authorization` 헤더로 토큰을 교체하는 방식이라 팀에 익숙하다.

JWT의 `exp`는 서명된 토큰 안에 있어서 **수명을 늘리려면 새 JWT를 발급**해야 한다. 따라서:

| 항목 | 설계 |
| --- | --- |
| 새 토큰 전달 | 응답 헤더 `Access-Token`(제안, `backend-contract/conventions.md`). 클라이언트는 응답마다 헤더를 확인해 있으면 **토큰을 교체**한다. 웹(브라우저 JS)이 읽으려면 서버가 `Access-Control-Expose-Headers`를 보내야 한다 |
| 교체 위치 | API 클라이언트가 세션 저장소(메모리)를 갱신. React 밖에서도 접근 가능해야 한다 (zustand 비영속 store 등) |
| 병렬 요청 | 응답이 겹쳐 와도 마지막 값으로 덮어쓴다. 서버는 아직 유효한 이전 토큰도 받아줘야 한다 (계약 필요) |
| 401 | 즉시 로그아웃 + 로그인 화면. 재시도/refresh 없음. 로그아웃 시 **쿼리 캐시도 비운다** (다음 사용자에게 데이터가 남지 않게) |
| 앱 백그라운드 | 포그라운드 복귀 시 마지막 활동 후 경과 시간이 토큰 수명(약 10분)을 넘었으면 서버 호출 전에 로그아웃 (UX 편의, 판단의 주체는 서버) |
| WebView | 웹이 API를 호출하며 서버가 새 토큰을 내려주면 **네이티브가 모르게 된다.** 웹 → 앱 브리지로 새 토큰을 전달하거나, 웹 호출은 앱이 중계하는 방식 중 택해야 한다 (`webview.md`) |
| 요청 | `Authorization: Bearer <access>`. URL/쿼리/로그에 토큰 금지 |
| payload | 개인정보를 claim에 넣지 않는다. 앱은 payload를 데이터 출처로 쓰지 않고 `exp`는 UX용 |

## 서버에 확인할 계약

1. 새 토큰을 내려주는 헤더 이름과 임계값(10분)·연장 길이, 절대 상한.
2. 이전 토큰을 만료 전까지 계속 받아주는가 (병렬 요청 안전).
3. 로그아웃 시 서버 측 폐기(블랙리스트)가 있는가. 없으면 로그아웃해도 토큰은 만료까지 유효하다.
4. 로그인 응답 코드 체계와 오류 형식 (`api-conventions.md`).
5. 기기 바인딩/추가 인증 응답 (`device-binding.md`, `docs/backend-contract/auth-device.md`). 서버 계약 초안과 DDL은 `docs/backend-contract/`에 있다.

## 레거시 참고

레거시도 토큰을 메모리에만 두고 응답 헤더로 교체하며 401이면 로그아웃했다 (자동 로그인 없음). 새 앱 정책과 같은 방향이라 동작 이전이 쉽다. 레거시는 로그인 ID/비밀번호를 Keychain에 저장하는 코드가 있었는데, 새 앱은 계승하지 않는다 (앱 실행마다 로그인 필수 정책과 충돌).
