# WebView 전략

## 방침

- 가맹점 / 거래내역 등 **데이터 화면은 별도 React 웹 프로젝트**를 만들어 앱에서 `react-native-webview`로 연다. 웹 코드는 이 저장소에 두지 않는다 (web 플랫폼도 쓰지 않음).
- 이유(사용자 결정): 오류가 났을 때 앱 배포 없이 웹을 수정해 바로 대응하기 위함.
- "다른 유명 회사들도 WebView로 한다"는 점은 이 세션에서 검증하지 못했다. 근거로 쓰지 않는다.
- `react-native-webview`는 Expo 번들 모듈 목록에 있다 (14.0.1). 구현 시 `npx expo install react-native-webview`.

## 네이티브 vs WebView (레거시 화면 목록 기준 초안)

레거시 앱 분석에서 데이터/표 중심으로 보인 화면을 WebView 후보로 분류했다 (`docs/migration/mms-mobile.md`).

| 구분 | 화면 |
| --- | --- |
| 네이티브 유지 | 로그인, OTP, 비밀번호 변경, 카드 OCR 결제(카메라), 수기결제, 생체인증, 설정, 하단 탭 |
| WebView 후보 | 거래내역/실패내역, 입금/부가세 리포트(합계·상세), SMS·선결제 이력, 가맹점 목록/상세 |
| 미정 | 홈 대시보드(카드/차트), 공지/FAQ(현재 API가 내려주는 HTML을 네이티브로 렌더) |

## 안전하게 하기 (검색 결과 기반, 공식 보안 문서로 재확인 필요)

- `originWhitelist`를 허용 도메인으로 좁힌다. 기본값(모든 출처)은 운영에 안전하지 않다.
- `onMessage`/`postMessage`는 출처를 지정할 수 없어, 예상 밖 문서가 로드되면 악용될 수 있다. 모든 메시지를 **신뢰하지 않는 입력**으로 보고 앱에서 검증한다.
- 토큰 전달은 쿠키 동기화보다 **헤더 또는 로드 후 주입**이 안정적이라는 자료가 있다. URL 쿼리스트링에는 넣지 않는다.
- 로그인은 WebView 안에서 하지 않는다 (OAuth 제공자가 임베디드 WebView 로그인을 막는 경우가 있다는 자료).
- 레거시 앱에는 실제 웹페이지를 여는 WebView, 브리지, 인증 전달이 **없다** (공지/FAQ HTML 렌더용으로만 의존성이 있음). 따라서 아래 계약은 전부 신규 설계다.

## 웹 ↔ 앱 계약 (초안, 웹 프로젝트와 합의 필요)

| 항목 | 초안 |
| --- | --- |
| URL | 환경별(dev/staging/prod) 베이스 URL을 `EXPO_PUBLIC_*`로 주입하고 `core/config/env.ts`에서 검증 |
| 인증 | 네이티브 로그인 → 토큰을 WebView 요청 헤더로 전달. 만료/401은 웹이 앱에 `AUTH_EXPIRED` 메시지로 알리고 앱이 로그아웃 처리. **슬라이딩 만료로 서버가 새 토큰을 내려주면 웹이 `TOKEN_UPDATED` 메시지로 앱에 전달해야 한다** (`auth-jwt.md`). refresh token은 없다 |
| 메시지 | `{ type, version, payload }` 형태의 타입 있는 스키마. 앱은 허용된 `type`만 처리 |
| 언어 | 앱의 현재 언어(ko/en)를 웹에 전달 |
| 오류 | `onError`/`onHttpError` → 네이티브 오류 화면(재시도, 닫기) + 오류 리포팅 |
| 뒤로가기 | Android 하드웨어 뒤로가기는 웹 히스토리 우선, 없으면 네이티브 스택 pop |
| 레이아웃 | 앱이 safe area와 하단 탭 인셋을 처리하고 웹은 그 안쪽만 그린다 |
| 권한 | 사용자 타입은 서버가 토큰으로 판단. 앱이 웹에 타입을 넘겨 신뢰시키지 않는다 |

## 구현 위치 (예정, 미구현)

`shared/ui/web-screen/` — 허용 도메인, 헤더, 브리지, 오류 처리를 한 컴포넌트에 모으고, 각 feature의 screen은 URL 경로만 지정한다.

## 미정 (사용자 확인 필요)

1. 웹 프로젝트가 인증을 헤더(Bearer)로 받는가, 쿠키인가?
2. 운영/스테이징 웹 도메인과 허용 목록.
3. 오프라인/네트워크 오류 시 네이티브 폴백 화면의 범위.
